## 1. Executive Summary & Objective

The **Follow XESTUS** system enables developers, clients, enterprise partners, and AI researchers to subscribe to meaningful, high-signal technical updates from XESTUS.

### Update Dispatch Categories
1. **Breakthrough Innovations & R&D Tracks** (Multi-Agent Swarm DAGs, MCP Protocol integrations, Edge SLMs).
2. **Major Product & Enterprise Platform Releases**.
3. **Engineering Portfolio & Case Study Publications**.
4. **Company & Founder Announcements**.

### Multi-Point Entry Points:
1. **Desktop Navbar**: Compact `.btn-nav-follow` in `.nav-actions` with bell icon.
2. **Hero Section**: Secondary `.hero-btn-follow` alongside the primary exploration CTA with supporting microcopy.
3. **Dedicated Follow Section (`#updates`)**: Complete explanatory card with guarantees and 1-click subscription trigger.
4. **State Synchronization**: Subscribing or unfollowing automatically syncs all 3 buttons simultaneously across the DOM in the active user language.

### Key Architectural Constraints
1. **GitHub Pages Static Compatibility**: The client does not require an active backend server to operate. In static mode, it securely leverages EmailJS with scope `[Follower Subscription]` to notify the admin mailbox (`xestus.office@gmail.com`).
2. **Backend API Extensibility**: When a private API endpoint is configured (`window.XESTUS_CONFIG.followApiEndpoint`), the client automatically mirrors subscriber registration to the private backend.
3. **Zero Public Exposure**: Subscriber lists and emails are NEVER stored in public JSON files or client-readable assets.
4. **Local Device Preference**: The subscriber's active state is kept only on their personal device via `localStorage.getItem('xestus_following_subscriber')`.

## 3. Data Models & Schemas

### 3.1. `Subscriber` Model
```typescript
interface Subscriber {
  id: string;                      // UUIDv4 (generated by backend/admin)
  email: string;                   // Normalized lowercase RFC 5322 email
  status: "ACTIVE" | "UNSUBSCRIBED" | "BOUNCED";
  channels: {
    email: boolean;                // Email briefing opt-in
    webPush: boolean;              // Web push notification opt-in
  };
  consent: {
    given: boolean;                // Explicit user opt-in
    timestamp: string;             // ISO-8601 UTC timestamp
    ipHash?: string;               // Pseudonymized SHA-256 IP hash (backend only)
    userAgent?: string;            // Client User-Agent string
  };
  createdAt: string;               // ISO-8601 UTC timestamp
  updatedAt: string;               // ISO-8601 UTC timestamp
}
```

### 3.2. `PushSubscription` Model
```typescript
interface PushSubscriptionRecord {
  subscriberId: string;
  endpoint: string;                // Push service endpoint URI
  expirationTime: number | null;
  keys: {
    p256dh: string;                // Elliptic curve Diffie-Hellman public key
    auth: string;                  // Authentication secret
  };
  registeredAt: string;            // ISO-8601 UTC timestamp
}
```

### 3.3. `Notification` / Update Dispatch Model
```typescript
interface NotificationDispatch {
  id: string;                      // Unique dispatch identifier (e.g. "xestus-ann-2026-001")
  category: "INNOVATION_LAB" | "PLATFORM_RELEASE" | "CASE_STUDY" | "ANNOUNCEMENT";
  title: string;                   // Brief headline (< 60 chars)
  summary: string;                 // Plain text overview (< 240 chars)
  url: string;                     // Target canonical destination URL (e.g. "https://xestus.in/#lab")
  publishedAt: string;             // ISO-8601 UTC timestamp
  author: string;                  // "Sudip Khatua / XESTUS Engineering"
  channels: ("EMAIL" | "PUSH")[];
}
```

### 3.4. `NotificationDelivery` Log Model
```typescript
interface NotificationDeliveryLog {
  deliveryId: string;
  notificationId: string;
  subscriberId: string;
  channel: "EMAIL" | "PUSH";
  status: "DELIVERED" | "FAILED" | "OPENED" | "CLICKED";
  dispatchedAt: string;
  errorMessage?: string;
}
```

## 5. Admin Publishing & Distribution Workflows

### 5.1. Admin Publishing Workflow (Future Backend / Private Admin Dashboard)
1. **Authentication**: Admin authenticates using multi-factor credentials via private API gateway.
2. **Drafting Update**: Admin drafts title, markdown body, canonical link, and selects delivery channels (`EMAIL`, `PUSH`).
3. **Validation & Preview**: Preview rendering across desktop and mobile formats with test email dispatch to `xestus.office@gmail.com`.
4. **Queue & Dispatch**:
   - Web Push payloads signed with VAPID private key dispatched to active `PushSubscription` endpoints.
   - Batch email dispatch sent with automated 1-click unsubscribe headers (`List-Unsubscribe`).
5. **Telemetry & Delivery Logs**: Record delivery metrics (Deliveries, Open rate, CTR) in private storage.

### 5.2. Static Mode Publishing (Current Implementation)
- In GitHub Pages static hosting, newly registered followers notify the executive inbox.
- Founder / Engineering lead manages broadcasts directly to verified followers via secure BCC / mailing list automation.

## 6. Privacy & Security Safeguards

- **No Public Data Exposure**: Zero subscriber email addresses or PII are stored in public Git repositories or public JSON endpoints.
- **GDPR & Privacy Compliance**:
  - Explicit opt-in checkbox required prior to form submission.
  - Zero third-party trackers or ad network beacons.
  - Instant local device revoke / unfollow capability.
- **Input Sanitization**: Email field enforced by regex validation, input length restrictions, and HTML entity encoding.
- **Service Worker Isolation**: `sw.js` restricts scope strictly to the root origin and verifies notification click URLs against trusted domain `https://xestus.in`.

## 7. Service Worker & Web Push Specification

- **File**: [`sw.js`](file:///s:/XESTUS/07_Website/GitHub/xestus-website/sw.js)
- **Scope**: `./`
- **Events Handled**:
  - `install`: Skips waiting to activate immediately.
  - `activate`: Claims clients to ensure immediate control.
  - `push`: Parses incoming JSON payload `{ title, body, icon, url }` and triggers `self.registration.showNotification()`.
  - `notificationclick`: Focuses existing open browser tabs on `https://xestus.in` or opens a new tab navigating to the target payload URL.
